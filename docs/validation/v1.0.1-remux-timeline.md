# Remux timeline regression validation

## Regression case

The regression test models a source with matching 1427.000000-second video and
audio streams. Its stream-copy candidate reports video duration 1428.428867
seconds and audio duration 1427.000000 seconds.

The validator calculates:

- source A/V duration delta: `0.000000` seconds
- candidate A/V duration delta: `+1.428867` seconds
- introduced A/V drift: `+1.428867` seconds

The candidate is rejected with `StreamDurationChanged` and
`AudioVideoDriftIntroduced` before replacement. The 0.000411-second video
start-time rounding is accepted because it is inside the 0.01-second start-time
tolerance. This demonstrates why a global 2-second container-duration check
was insufficient.

## Rules

For each audio and video stream, the validator compares stream index, order,
codec type/name, time base, start time, and duration. It uses a 0.05-second
duration tolerance and a 0.01-second start-time tolerance. It also compares
every source video/audio duration relationship with the corresponding candidate
relationship. Subtitle, attachment, and data streams are still protected by
identity/order checks, but do not require duration/start-time values.

Unknown audio/video duration or start time cannot prove timeline preservation,
so automatic replacement fails closed. The queue records a stable reason code.
After the writable candidate is swapped into place, the same validation runs
again; any mismatch triggers rollback from the verified backup.
