# v1.1.1 temporal video stream eligibility

Source A/V diagnostics only compare a video stream when it has a usable temporal timeline: `codec_type=video`, `attached_pic` is false, and the stream-local duration is finite and strictly positive. A zero, negative, invalid, or absent duration is excluded. This rule is centralized in `TemporalVideoStreamPolicy` and is shared by descriptor and packet analyses.

The rule deliberately does not inspect codec, dimensions, file name, or container duration. Therefore a temporal MJPEG stream remains eligible, while an attached illustration or a zero-duration video stream is excluded. No audio stream policy changes. Exclusion only prevents diagnostic pairs; it does not alter remux validation, repair eligibility, or source media.

## Raspberry Pi 4 validation

The exact 1.1.1 package was installed on the ARM64 Jellyfin runtime with `DryRun=true`, `AllowRepairOfCorrupted=false`, `MaxRepairsPerRun=1`, and packet analysis disabled. A read-only real-library inspection found a media item with two excluded zero-duration illustration streams and verified zero A/V diagnostics against their original stream indexes. It also found an independent long source A/V mismatch and retained `AudioVideoDurationMismatch`, `AudioVideoEndMismatch`, and `AudioVideoDriftSuspected`.

The 129-file scheduled scan completed in 17.59 seconds with 18 affected media, 60 source A/V diagnostics, and an empty repair queue. This is down from the prior 20 affected media and 74 diagnostics. Packet analysis completed in 38.67 seconds with the same 18 affected media, 63 diagnostics including 3 packet drift warnings, and an empty queue. The targeted zero-duration illustration streams produced no packet drift warning. Configuration, queue, and last-scan data were restored after each scan; source media was not written. Short authenticated media reads and system-information requests completed during both scans.
